# Lunex stage2 — отчёт проверки архива

Дата: 12 октября 2026 г.

## Результат

Архив содержит исходники Android-клиента (Kotlin/Jetpack Compose), отдельного веб-клиента React/Vite и Node.js-сервера. Это не готовый APK: в архиве нет собранного `app-debug.apk`, а локальная Android-сборка в доступной среде не запустилась.

## Проверки

- Архив успешно распакован; структура и ключевые файлы прочитаны.
- `node --check Lunex-MVP/server/index.js` — успешно.
- `node --check Lunex-MVP/server/security.js` — успешно.
- `npm test` — 9 passed, 2 failed-to-start: обоим интеграционным тестам не удалось импортировать `socket.io-client`, потому что зависимости отсутствуют.
- Установка зависимостей превысила тайм-аут.
- Android build не запускался: отсутствуют Gradle/Wrapper и Android SDK.

## Найденные архитектурные моменты

1. Web MVP и Android — две разные архитектуры. Веб использует аккаунты и серверный API; Android создаёт локальный аккаунт и узел на устройстве. Совместная синхронизация между ними не подтверждена.
2. Веб-сервер хранит сообщения в JSON на сервере в открытом виде на прикладном уровне. Это не E2EE.
3. В Android-манифесте включён `usesCleartextTraffic=true`: удобно для прямых LAN-соединений, но небезопасно для незашифрованного трафика в недоверенной сети.
4. В `Lunex-MVP/docs/STATUS.md` прежний статус не отражал часть уже присутствующих web API (сообщества, вложения, signaling звонков). Документ обновлён с разделением найденного кода и фактически проверенных возможностей.
5. Отдельная `public/direct.html` — эксперимент с ручным SDP и без ICE-серверов; это ограничивает соединения через NAT и не обеспечивает анонимность.

## Не проверено

- Сборка web bundle и полноценные интеграционные тесты.
- Компиляция Kotlin, создание APK и установка на устройство.
- Фактические звонки, работа транспорта между двумя физическими телефонами и передача файлов в разных сетевых условиях.
- Криптографическая корректность и независимый аудит безопасности.

## Что нужно для следующего этапа

Нужна среда с доступом к npm registry, Gradle 8.13, JDK 17 и Android SDK либо успешный запуск соответствующих GitHub Actions. До успешной сборки и проверки на устройстве проект нельзя считать релизно готовым.
