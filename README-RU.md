# Lunex — полный комплект проекта

Этот архив объединяет текущие исходники Lunex, Android-проект с фирменной иконкой, документацию по прошлым задачам и сохранённые ZIP предыдущих итераций.

## Структура

- `Lunex-MVP/` — основной веб-мессенджер и сервер (React/Vite, Node.js/Express/Socket.IO).
- `Lunex-Android/` — Android-проект на Kotlin/Jetpack Compose и workflow GitHub Actions для сборки APK.
- `branding/Lunex-Official-Icon.png` — оригинальная картинка, предоставленная пользователем; файл скопирован без изменения.
- `history/previous-releases/` — сохранённые архивы прошлых версий, как они были доступны в рабочем каталоге.
- `PROJECT-HISTORY-RU.md` — сводка исходной задумки и накопленных требований.

## Исходная задумка Lunex

Lunex задуман как мессенджер между Telegram и Discord: личные сообщения, групповые чаты, сообщества/серверы, текстовые и голосовые каналы, роли и права, звонки, обмен файлами и медиа. Интерфейс должен глубоко настраиваться: фон для каждого чата, цвета, прозрачность, blur, шрифты, размеры, формы пузырей, анимации и импорт/экспорт тем.

Приватность — ключевое требование: сквозное шифрование, минимум метаданных, независимая инфраструктура доставки и исследование многоступенчатой маршрутизации. Нельзя считать эти свойства реализованными только на основании описания или наличия прототипа.

## Сводка предыдущих задач и требований

### Клиент и визуальный стиль
- Название продукта: Lunex.
- Тёмная тема и фиолетово-синее свечение логотипа.
- Использовать предоставленную пользователем картинку как фирменную иконку.
- Android-приложение и веб-клиент должны развиваться в едином проекте.
- Гибкая система тем и настройка оформления отдельных чатов.

### Мессенджер
- Регистрация и вход.
- Личные сообщения и сообщения в каналах.
- Сообщества, каналы и роли/права доступа.
- Голосовые/видеозвонки, медиа и файлы — требуемые функции, но требуют отдельной реализации и проверки.
- Не заявлять, что функция готова, если она не реализована и не протестирована.

### Безопасность и приватность
- Не хранить пароли в открытом виде; применять проверенное хэширование паролей.
- Ограничивать размеры запросов и частоту сообщений, проверять Origin и права доступа.
- Сквозное шифрование должно быть устроено так, чтобы сервер не получал открытый текст. Текущая серверная реализация MVP не обеспечивает это для обычных каналов.
- Onion/mixnet-маршрутизация и децентрализованная доставка — желаемое направление, не готовая функция.
- P2P/WebRTC-эксперимент из ранних итераций не равен production-grade E2EE и может не соединяться через NAT без сигналинга/STUN/TURN.

### Разработка и релизы
- Сохранять исходники, документацию и версии.
- Перед релизом проверять тесты, сборку веб-клиента и сборку Android APK.
- Собирать APK в GitHub Actions; загружать результат как artifact.
- Не публиковать секреты, токены, пароли или приватные ключи в репозитории.

## Статус и ограничения

Это комплект исходников и прошлых архивов, а не утверждение, что всё из исходной задумки уже работает. Перед установкой или публичным запуском необходимо запустить сборку и проверить зависимости. APK в этом комплекте не гарантируется: Android workflow должен успешно выполниться на GitHub Actions. Веб-MVP также требует проверки полноценной production-сборки и отдельного аудита безопасности.

## Как собрать веб-MVP

В каталоге `Lunex-MVP/`:

```bash
npm install
npm test
npm run build
```

Для запуска сервера и клиента см. `Lunex-MVP/README.md`.

## Как получить Android APK

1. Загрузить содержимое `Lunex-Android/` в репозиторий GitHub (сохранить путь `.github/workflows/build-apk.yml`).
2. Открыть вкладку Actions и запустить workflow `Build Lunex APK`.
3. После успешной сборки скачать artifact `Lunex-debug-apk`.
4. Проверить APK на устройстве. Debug APK не является подписанным production-релизом для Google Play.
